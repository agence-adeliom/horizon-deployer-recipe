# Authentification HTTP par .htpasswd : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** ajouter au recipe les tâches `http-auth:setup`, `http-auth:update`, `http-auth:remove` et la réinjection `deploy:http-auth`, qui protègent une préproduction par `.htaccess` + `.htpasswd`.

**Architecture :** des fonctions pures `httpAuth*` (bloc `.htaccess`, ligne `.htpasswd`, garde-fou) testées sans hôte, une plomberie distante bâtie sur `transferRun()` / `transferResolvePath()` comme le reste du recipe, puis les quatre tâches. Le garde-fou production réutilise la lecture de `shared/.env` de `roles:check`, rendue commune.

**Stack :** PHP 7.4 à 8.4, Deployer 7.4+ et 8, bash et curl côté serveur, Apache 2.4 côté hébergement.

**Spec :** `docs/specs/2026-11-26-http-auth.md` (à lire en entier avant toute tâche).

## Contraintes globales

- Tout le code vit dans `recipe/horizon-transfer.php`, namespace `Deployer`, fonctions globales préfixées `httpAuth` (nouvelles) ou `transfer` (communes).
- Compatible PHP 7.4 : ni paramètres nommés, ni `match`, ni types d'union.
- Jamais d'appel direct à `run()` / `runLocally()` avec options : passer par `transferRun()` (voir CLAUDE.md).
- Toute lecture de configuration d'un hôte passe par `transferResolve($env, ...)`, `transferResolvePath($env, ...)` ou `on($env, ...)`.
- Chemins et valeurs dans les commandes : toujours `escapeshellarg()`.
- Toute question qui écrit a `false` pour défaut et passe par `transferConfirm()` ; rien n'est écrit en `-n`.
- Le mot de passe en clair n'apparaît dans aucune commande envoyée, locale ou distante (`-vvv` les affiche).
- Réglages par défaut (copiés de la spec) : `http_auth` = `false`, `http_auth_user` = `'adeliom'`, `http_auth_realm` = `'Accès restreint'`, `http_auth_htaccess` = `'web/.htaccess'`, `http_auth_htpasswd` = `'{{deploy_path}}/shared/.htpasswd'`, `http_auth_except_paths` = `['/.well-known/acme-challenge/']`, `http_auth_allow_ips` = `[]`.
- Marqueurs du bloc, exacts : `# BEGIN Horizon HTTP auth` et `# END Horizon HTTP auth`.
- Mot de passe généré : 24 caractères tirés de `abcdefghjkmnpqrstuvwxyzABCDEFGHJKLMNPQRSTUVWXYZ23456789`, par `random_int()`.
- Messages affichés, commentaires et README en français, écriture inclusive au point médian, formulations épicènes de préférence.
- Commits en français, format conventionnel. Pas de tag avant le merge.
- Aucune tâche ne crée de répertoire de travail : pas de triptyque `transferResetState()` / `transfer:cleanup`. La sonde nettoie son dossier elle-même (`try/finally`).

## Points de vigilance

Entrées que la spec implique sans les nommer, avec le test qui les couvre :

1. **`.htaccess` en fins de ligne CRLF, ou sans saut de ligne final** : le reste du fichier est conservé octet pour octet. Tests dans la tâche 2.
2. **Bloc tronqué ou modifié à la main** (`BEGIN` sans `END`, `END` avant `BEGIN`, deux blocs) : `\UnexpectedValueException`, fichier jamais réécrit. Tests dans la tâche 2.
3. **`WP_HOME` avec barre finale ou sous-dossier** (`https://site.test/`, `https://site.test/fr`) : l'URL de la sonde se construit sans double barre. Tests dans la tâche 3.
4. **`deploy_path` en `~/`** (mutualisé) : `AuthUserFile` reçoit un chemin absolu. Test dans la tâche 5.
5. **Mot de passe avec `"`, `\`, `$`, `'` ou espace** : hash valide pour `password_verify()`, fichier de configuration curl correctement échappé, clair absent des commandes. Tests dans les tâches 2, 3 et 5.

### Tâche 2 : fonctions pures du bloc, du .htpasswd et du garde-fou

**Fichiers :**
- Modifier : `recipe/horizon-transfer.php` (nouvelle section "Authentification HTTP" avant la section des points d'accroche, ligne ~4015 ; les sept `set()` avec les autres défauts, après `transfer_backup_keep` ligne ~180)
- Créer : `tests/unit/http-auth.test.php`

**Interfaces :**
- Consomme : `transferEnvironmentType()` (tâche 1).
- Produit :
  - `httpAuthBlock(string $htpasswdPath, string $realm, array $ips, array $exceptPaths): string` : bloc complet, marqueurs compris, terminé par `"\n"`. IP : `127.0.0.1` et `::1` en tête, puis `$ips` dans l'ordre, sans doublon, sur une seule ligne `Require ip`. Une ligne `Require expr %{REQUEST_URI} =~ m#^<préfixe>#` par chemin, préfixe passé par `preg_quote($p, '#')`. `$realm` : `"` et `\` échappés par `\`.
  - `httpAuthInsertBlock(string $htaccess, string $block): string` : retire le bloc existant puis place `$block` en tête. Fichier vide : `$block` seul.
  - `httpAuthRemoveBlock(string $htaccess): string` : retire le bloc et la ligne vide qui le suit. Sans bloc : texte inchangé.
  - `httpAuthBlockIps(string $htaccess): array` : IP de la ligne `Require ip` du bloc, hors `127.0.0.1` et `::1`. Sans bloc : `[]`.
  - Les trois dernières lèvent `\UnexpectedValueException` si le bloc est mal formé (marqueur seul, ordre inversé, deux blocs).
  - `httpAuthGeneratePassword(): string`.
  - `httpAuthHtpasswdLine(string $user, string $password): string` : `"$user:" . password_hash($password, PASSWORD_BCRYPT) . "\n"`. `\InvalidArgumentException` si `$user` est vide ou contient `:`, `\r` ou `\n`.
  - `httpAuthHtpasswdUser(string $content): ?string` : identifiant de la première ligne non vide, `null` sans ligne.
  - `httpAuthProductionRefusal(array $values, bool $protected): ?string` : message de refus, ou `null` pour continuer. Refus si `transferEnvironmentType($values)` vaut `production` (le message cite la variable et sa valeur, et suggère `WP_ENV=staging` si la valeur n'est pas `production`) ou s'il vaut `null` avec `$protected` vrai.

### Tâche 3 : plomberie distante et sonde Apache

**Fichiers :**
- Modifier : `recipe/horizon-transfer.php` (section "Authentification HTTP")
- Tests : `tests/unit/http-auth.test.php`

**Interfaces :**
- Consomme : `transferRun()`, `transferResolvePath()`, `transferTest()`.
- Produit :
  - `httpAuthHtaccessPath(Host $env, string $root): string` : `$root` vaut `'{{current_path}}'` ou `'{{release_path}}'`. Résout `"$root/{{http_auth_htaccess}}"` par `transferResolvePath()`, puis `readlink -f` sur l'hôte (repli : chemin non résolu si `readlink` ne rend rien). Un `.htaccess` partagé désigne donc le fichier de `shared/`.
  - `httpAuthReadFile(Host $env, string $path): ?string` : `null` si le fichier n'existe pas. Lecture en base64 (`base64 < f`), décodée après suppression des blancs, pour garder le contenu intact.
  - `httpAuthWriteFile(Host $env, string $path, string $content, string $mode): void` : contenu passé en base64 (`printf %s <b64> | base64 -d > <tmp>`), `chmod`, puis `mv` sur la cible. Fichier temporaire dans le même dossier, nommé `<cible>.horizon-tmp`.
  - `httpAuthHttpStatus(?Host $env, string $url, ?string $user = null, ?string $password = null): ?int` : `curl -sS -o /dev/null -w '%{http_code}' --max-time 20`, local si `$env` vaut `null`, `null` si curl échoue. Avec identifiants : un fichier de configuration curl temporaire (`user = "<id>:<mdp>"`, `"` et `\` échappés par `\`, droits `600`) passé par `-K`, supprimé dans un `finally`. Uniquement en local : le clair ne va jamais sur le serveur.
  - `httpAuthProbe(Host $env, string $webRoot, string $url): array` : renvoie `['status' => 'ok'|'ignored'|'error'|'unreachable', 'code' => ?int, 'ip' => ?string]`. Déroulé de la spec, section "Sonde Apache". Dossier `horizon-http-auth-` + `bin2hex(random_bytes(6))` sous `$webRoot`, contenant `.htaccess`, `.htpasswd` vide et `index.php` (`<?php echo $_SERVER['REMOTE_ADDR'];`). URL de la sonde : `rtrim($url, '/') . '/<dossier>/'`. 401 donne `ok`, 200 `ignored`, 500 `error`, `null` ou autre code `unreachable`. Sur `ok` seulement : `.htaccess` vidé, puis `curl -fsS` lancé depuis le serveur ; une sortie qui passe `FILTER_VALIDATE_IP` devient `ip`. `rm -rf` du dossier dans un `finally`, après vérification que le chemin contient `/horizon-http-auth-`.
